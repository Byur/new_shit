# DeepSeek Harness 插件生态视频策划

## 学习承诺

看完后，观众能用一个准确的心智模型理解 DeepSeek Harness（`dsh`）：它不是把所有能力焊死在一个 Agent 里，而是由 Cordis 管理、按能力装配的插件运行时。观众还能区分官方内置能力与社区插件，并知道安装前要核对来源、维护状态和宿主版本。

## 范围与边界

- 目标身份：DeepSeek AI 的开源 DeepSeek Harness，简称 `dsh`。
- “常用”的口径：优先选择官方仓库中 shipped/profile 组合里反复出现的核心能力；社区部分只选有原始仓库、发布记录和兼容性说明的代表案例。
- 不做：社区插件排行榜、运行时安全背书、未经源代码核实的能力承诺。
- 重要提醒：官方仓库把项目标为 developer preview，并明确提示可能存在兼容性破坏；视频不把预览期插件描述成稳定标准。

## 叙事主线

五个能力不是五张平铺的卡片，而是一条从问题到可验证结果的“装配轨道”：

`Goal → Bash 落地 → Web 求证 → MCP 取上下文 → Subagent 分工 → 社区团队扩展 → Review`

每个插件都通过一个具体动作出现：命令留下退出标记、搜索留下来源、MCP 资源进入会话、子 Agent 回传结果、社区团队展开任务依赖。这样观众看到的是能力边界和代价，而不是名词清单。

## 片尾选择规则

1. 先确认原始仓库和包名；不要只相信第三方目录的描述。
2. 再看维护信号：最近提交/发布、README 的宿主版本矩阵、构建与安装说明。
3. 最后看权限与兼容性：shell、网络、文件、依赖脚本以及宿主版本是否匹配。
4. “星数高”只说明可见度，不等于安全、稳定或适合当前 profile。

## 视觉提案

**“把 Agent 做成一块可插拔的轨道板。”**

用深色工作台、发光端口、边界线和事件轨迹呈现插件架构。每一段都让一个插件把空端口变成可观察的证据；连续场景保留同一条中央轨道，切换焦点时压暗上下文，避免把五个能力误读成互不相干的卡片。
