一个 Agent，除了模型，还需要什么？答案可能不是再换一个模型，而是把能力装配起来。

这就是 DeepSeek Harness，简称 dsh。它是 DeepSeek AI 开源的代理运行时，基于 Cordis，把工具、会话、沙箱、子 Agent 和界面都做成可组合的插件。先提醒一句：官方仍把它标为 developer preview，版本可能发生不兼容变化。

我们沿着一条任务轨道，看五个常见选择。

第一站是 Bash。官方的 dsh-tool-bash 暴露 bash 工具，让 Agent 执行命令，并返回标准输出、错误和退出标记。它可以接本地执行器，也可以接沙箱执行器；如果要跑后台任务，还要继续装配任务运行时。重点不是“能执行”，而是结果留下了可判断的边界。

第二站是 Web。dsh-tool-web 提供 web_search 和 web_fetch：先发现当前信息，再读取具体页面；搜索结果会保留来源 URL。官方文档还特别强调，返回内容属于外部、不可信数据。检索能力越强，来源和边界就越重要。

第三站是 MCP 资源。dsh-mcp-resources 不是替你猜服务器，而是要求先配置 MCP server，再列出资源或模板，最后按 URI 读取。资源按需进入会话；没有配置服务器时，这些工具也不会凭空出现。

第四站是 Subagent。dsh-subagent 加上 dsh-tool-subagent，可以把一个任务交给子 Agent，再收回结果，或者继续后续对话。但它不是单包魔法：还需要 provider 和对应工具一起装配。

第五站来自社区。AgentTeams 把当前会话变成 captain，创建带依赖的任务和成员，并在 Web UI 里观察团队。它不是官方内置能力；原始仓库当前给出的配对是 AgentTeams 0.1.22 对 DeepSeek Harness 0.2.0-rc.2。社区插件要看自己的发布记录和宿主版本，不能只看名字或星数。

所以，挑插件可以记住三步：先找原始仓库和准确包名；再看最近发布、兼容矩阵和构建说明；最后核对它需要的 shell、网络、文件和依赖脚本权限。热门只代表可见度，不等于安全或稳定。

DeepSeek Harness 的价值，不是给 Agent 塞进一份固定能力清单，而是让能力成为可以替换、组合和追踪的模块。模型负责思考，Harness 负责把思考接到真实环境里。片中信息以 DeepSeek 官方仓库、官方文档和 AgentTeams 原始仓库为准；安装前，请以最新版本说明为准。
